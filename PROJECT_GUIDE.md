# Sensor CV Algorithm Pipeline — Project Documentation 

---

## 1. One-minute elevator pitch

This is an **end-to-end grayscale denoising and analysis portfolio project** written in **Python**. It combines:

- **Classical image processing** (filters, edges, thresholding, morphology, connected components, Hough lines, interpolation)—the kind of stack familiar from **ISPs** and **embedded vision**.
- **Deep learning**: a **convolutional neural network** trained to predict **additive Gaussian noise** and reconstruct the image (**residual / noise-centric formulation**, related to **DnCNN**-style thinking).
- **Quantitative evaluation** using **PSNR** and **SSIM**.
- **Public data**: **STL-10** natural images, converted to **grayscale patches**, with **synthetic noise** and **data augmentation** so training resembles robustness to capture variability.

It is framed for roles that care about **image sensors**, **image quality**, and **algorithms from classical → learned**.

- **What it does:** Calls `torchvision.datasets.STL10` with `download=True` for both **`train`** and **`test`** splits under `--root` (default `./data`).

#### `scripts/export_docs_assets.py`

- **What it does:** Regenerates **all** PNGs and `run_summary.json` under `docs/assets/` using the same classical + metrics code paths as the package.
- **Why:** Keeps the GitHub Pages site visually synchronized with the actual implementation after code changes.

### 3.4 Core package (`src/`)

#### `src/__init__.py`

- Marks `src` as a Python package (minimal).

#### `src/classical.py`

- **Role:** Library of **classical image processing** primitives and one bundled **`analyze_gray`** pipeline for demos.
- **Major functions:**

  | Function / concept | What it does | Why it matters for sensors / ISP |
  |-------------------|--------------|-----------------------------------|
  | `convolve_gray` | 2D convolution with symmetric boundary handling; optional kernel normalization. | Foundational: every linear filter is a convolution; teaches locality and footprint. |
  | `gaussian_kernel_2d` / `gaussian_blur_gray` | Smoothing with Gaussian weights. | Pre-processing before edge detection; noise suppression vs blur trade-off. |
  | `median_blur_gray` | Non-linear order-statistic filter via OpenCV. | Excellent for **salt-and-pepper** impulses; preserves edges better than mean filters for impulsive noise. |
  | `bilateral_gray` | Edge-preserving smoothing (`sigma_color`, `sigma_space`). | Classic ISP-friendly enhancement: reduces noise without wiping sharp transitions. |
  | `sobel_edges_gray` | Gradient `Gx`, `Gy`, magnitude via Sobel. | Cheap directional derivatives; structure extraction. |
  | `canny_edges_gray` | Multi-stage edge detector (OpenCV). | Strong practical baseline for thin, contiguous edges; often after blur. |
  | `threshold_simple_gray` | Global fixed threshold. | Segmentation when illumination is uniform. |
  | `threshold_adaptive_gray` | Locally varying threshold (Gaussian-weighted neighborhood). | Handles shading / uneven lighting better than global thresholds. |
  | `threshold_otsu_gray` | Histogram-based automatic threshold (returns mask + chosen threshold). | Unsupervised split when bimodal histogram assumption roughly holds. |
  | `histogram_equalization_gray` | Spreads intensity histogram for visibility. | Legacy ISP contrast adjustment; still pedagogically important. |
  | `morph_ops_gray` | Erosion and dilation on binary masks. | Cleans segmentation masks: removes speckles (erode) or fills gaps (dilate). |
  | `connected_components` | Labels binary foreground regions (`cv2.connectedComponents`). | Object counting, blob analysis after thresholding. |
  | `label_centroids` | Centroids per label via SciPy `ndimage.center_of_mass`. | Summarize regions for visualization or downstream logic. |
  | `hough_lines_p` | Probabilistic Hough on edge maps; returns line segments. | Geometric reasoning on structured scenes (lines in architecture, UI, road markings—depending on domain). |
  | `resize_gray` | Scaling with **nearest / bilinear / bicubic** interpolation. | Foundational for pyramids, preview pipelines, and resolution changes on device. |
  | `analyze_gray` | Convenience bundle: blur → median → bilateral → Sobel on blurred → Canny on blurred → Otsu on blurred → histogram EQ on original. | Single-call narrative for demos; reveals **ordering matters** (e.g., blur stabilizes Canny). |

- **`ClassicalAnalysis` dataclass:** Structured outputs from `analyze_gray` so downstream code (e.g., `demo.py`) can access intermediate representations cleanly.

#### `src/dataset.py`

- **Role:** PyTorch `Dataset` feeding the CNN trainer.

- **`RandomGaussianNoise`:** For each patch, samples noise standard deviation **uniformly** in `[noise_min, noise_max]` (interpreted on a **0–255** scale, applied to tensors in **[0,1]**). Returns `(noisy_image, noise_tensor)` where `noise_tensor` is the exact additive residual.

- **`NoisyGrayPatchDataset`:**
  - Uses **STL-10** (`torchvision.datasets.STL10`).
  - Converts RGB PIL images → **single-channel** `[0,1]` tensors (`Grayscale`, `ToTensor`).
  - **Augmentation (training only):** random horizontal flip, vertical flip, `torch.rot90` by 0/90/180/270°, then **random crop** to `patch_size × patch_size` (default 64). If the native resolution were smaller than the patch (not typical for STL-10), it bilinearly resizes up.
  - **Why STL-10:** Public, manageable size, **96×96** RGB images → good for **patch-based denoising** without giant downloads.
  - **Why Gaussian noise range:** Simple **sensor read-noise toy model**; trains the network across **multiple SNR levels** in one schedule.

- **`collate_identity`:** Stacks batches into tensors for `DataLoader`.

#### `src/models.py`

- **`DenoiseCNN`:** Fully convolutional stack:
  - First layer: `Conv2d(1 → width, 3×3)`, **BatchNorm**, **ReLU**.
  - Middle: repeated `Conv2d(width → width, 3×3)`, BatchNorm, ReLU (`depth` controls total layers).
  - Last layer: `Conv2d(width → 1, 3×3)` with bias—outputs predicted **noise map** same spatial size as input.
- **Why this architecture:** Lightweight, trains on laptop/Colab; demonstrates **convolution + BN + nonlinear activations** clearly.
- **`restore_from_noise_prediction`:** Implements **`clean_hat = clamp(noisy − predicted_noise)`**—the **residual formulation**. Predicting **noise** rather than **clean image directly** is a standard stable trick (conceptually aligned with **DnCNN** literature).

#### `src/train.py`

- **Role:** Training CLI (`python -m src.train`).
- **Loop:** For each batch: forward → **MSE** between `pred_noise` and **ground-truth noise** → backward → Adam step.
- **Checkpoint:** Each epoch saves `weights.pt` containing `state_dict`, hyperparameters (`args`), and epoch index—so `demo.py` can reconstruct the exact network width/depth.
- **Device:** Uses CUDA if available.
- **Hyperparameters (defaults):** epochs, batch size, learning rate, patch size, noise min/max, optional subset of images for quick experiments, network depth/width.

#### `src/demo.py`

- **Role:** **Qualitative + quantitative** comparison on **one STL-10 test image** (index selectable).
- **Steps:**
  1. Load test image, convert to grayscale (`BT.601`-style weights on tensor channels).
  2. Add **Gaussian noise** with CLI-controlled σ (default 25).
  3. Apply **median** and **bilateral** classical denoisers.
  4. Run **`analyze_gray`** for visualization panels (blur, Sobel, Canny, hist eq, Otsu mask).
  5. **Connected components** on Otsu mask + centroid overlay for up to 50 blobs.
  6. **Interpolation demo:** nearest-neighbor upscale of a small crop (shows classical **resampling** behavior).
  7. If **`weights.pt`** is provided: load `DenoiseCNN`, predict noise, reconstruct, compute metrics.
  8. Save a **3×4 matplotlib montage** and print **PSNR/SSIM** table vs clean.

- This module is your **story of classical vs learned** on the **same noisy observation**.

#### `src/metrics.py`

- **`psnr_gray`:** Peak Signal-to-Noise Ratio vs reference (default data range 255).
- **`ssim_gray`:** Structural Similarity Index vs reference.
- **Why both:** PSNR is ubiquitous engineering metric; SSIM correlates better with perceived structure for many scenes—pairing them shows **thoughtful evaluation**.

## 4. End-to-end pipeline (execution order and data flow)

Think of the **full deep pipeline** as four conceptual stations:

### Stage A — Environment & dependencies

1. Create virtual environment (optional but recommended).
2. Install **PyTorch + Torchvision** (CUDA build on GPU machines; CPU wheel acceptable for short demos).
3. `pip install -r requirements.txt` for OpenCV, SciPy, scikit-image, Matplotlib, etc.

### Stage B — Data acquisition

Run:

```bash
python scripts/prepare_data.py --root ./data
```

**Flow:** Internet → STL-10 archives → local **`./data/`** cache consumed by `torchvision`.

### Stage C — Training (learned denoiser)

Run:

```bash
python -m src.train --data-root ./data --epochs … --batch-size … --out-dir ./outputs
```

**Flow:**

- `NoisyGrayPatchDataset` draws RGB STL-10 train images → grayscale tensor → augment → crop → add Gaussian noise.
- Model predicts noise; **MSE** trains parameters.
- **`outputs/weights.pt`** written each epoch (final epoch overwrites same filename by default).

### Stage D — Evaluation / storytelling figure

Run:

```bash
python -m src.demo --data-root ./data --weights ./outputs/weights.pt --out ./outputs/demo_compare.png
```

**Flow:**

- Reads **test** STL-10 image → synthesizes noise → classical outputs → optional CNN reconstruction → saves montage + prints metrics.

**Parallel “lightweight classical trail” (no PyTorch dataset dependency beyond skip):**

```bash
python scripts/classical_skimage_demo.py
```

Uses **`skimage`** sample image instead of STL-10—good when you only want to discuss **classical IP**.

**Website figure regeneration:**

```bash
python scripts/export_docs_assets.py
```

Rebuilds **`docs/assets/*.png`** for Pages—does **not** train CNN.

## 5. Algorithms:

### 5.1 Classical algorithms (what / why here)

| Algorithm | One-line idea | Why included |
|-----------|----------------|--------------|
| **Convolution / Gaussian blur** | Weighted local averaging; low-pass filter. | Noise suppression + precursor to stable gradients / Canny; teaches kernel footprint and trade-offs (blur vs detail). |
| **Median filter** | Replace pixel by neighborhood median. | Strong on **impulsive** noise (salt-and-pepper); robust outlier rejection. |
| **Bilateral filter** | Average neighbors that are **spatially close** and **similar in intensity**. | Edge-preserving smoothing—motivation matches many **tone/detail** discussions in imaging. |
| **Sobel** | Discrete derivative filters → gradient magnitude. | Cheap edge emphasis; explains **first-order** structure extraction. |
| **Canny** | Smooth → gradient → non-max suppression → hysteresis thresholding (OpenCV handles internally). | Strong baseline **edge map** for segmentation / Hough / descriptors downstream. |
| **Global / adaptive / Otsu thresholding** | Turn grayscale into binary regions via intensity cuts (manual, local, or histogram-optimal). | Classic segmentation front-end; adaptive & Otsu address non-uniform illumination / automatic split. |
| **Histogram equalization** | Remap intensities to use dynamic range more uniformly. | Illustrates global tone mapping; discuss **artifacts** (noise amplification) vs benefit (shadow lifting). |
| **Morphology (erode/dilate)** | Min/max filters on binary shapes. | Cleans masks; connects broken objects or removes pepper noise after thresholding. |
| **Connected components** | Label disjoint foreground regions. | Object counting / region proposals at lowest level. |
| **Hough transform (Probabilistic)** | Vote for lines from edge points; return segments. | Demonstrates **global geometric inference** from local edges. |
| **Interpolation (nearest/bilinear/bicubic)** | Resampling when changing resolution. | Fundamental for scaling pipelines and understanding aliasing vs sharpness costs. |

### 5.2 Deep learning algorithms & training choices

| Piece | Role | Why chosen |
|-------|------|------------|
| **Convolutional layers** | Spatially shared filters; local receptive fields grow with depth. | Natural match to images; standard CV backbone pattern. |
| **Batch normalization** | Stabilize activations / training dynamics in conv stacks. | Helps MSE-based regression converge reliably across noise levels. |
| **ReLU** | Non-linearity enabling composed feature extraction. | Standard, efficient. |
| **Residual noise prediction** | Predict **noise ε**, reconstruct **y − ε̂**. | Training stability and alignment with classical **additive noise** assumption; literature connection (**DnCNN**). |
| **MSE loss** | Penalize squared error between predicted and true noise maps. | Straight supervised objective for Gaussian corruption; simple to explain and debug. |
| **Adam optimizer** | Adaptive first-order optimization. | Practical default for small networks without extensive tuning. |
| **Data augmentation** | Flips, rotations, random crops. | Increases effective diversity—proxy for orientation / framing variability in capture. |
| **Patch-based training** | Train on small crops (e.g., 64×64). | Memory-efficient; exposes the model to many contexts per epoch—standard in restoration literature. |

### 5.3 Evaluation metrics

| Metric | Meaning (short) | Why mention both |
|--------|------------------|------------------|
| **PSNR** | Log-scale fidelity vs reference (dB). | Ubiquitous engineering number—easy to compare methods. |
| **SSIM** | Perceived structural similarity (luminance, contrast, structure). | Often aligns better with **edges / structure** preservation critiques—pairs well when bilateral vs CNN debate arises. |

## 6. Honest limitations 

- **Synthetic Gaussian noise** is **not** a complete camera noise model (no Poisson photon noise, no ISP-specific banding, no CFA demosaic artifacts).
- **STL-10 grayscale conversion** is a pedagogical simplification; real sensors have **Bayer**, **black level**, **gain**, **tone mapping**, etc.
- **Small CNN** prioritizes clarity over state-of-the-art restoration scores.
- **demo.py** CNN inference on a **full 96×96 frame** while training on **patches** is acceptable for a demo but in production you’d discuss **border artifacts**, **tiling**, or **fully convolutional** sliding-window policies at scale.
- **GitHub Pages** shows **precomputed** figures—not live inference.
